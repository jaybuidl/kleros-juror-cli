## Agent Brief

**Category:** enhancement (documentation)

**Summary:** Every timing surface documents the hazard that a period can end *early*; none documents
that a period's clock starts when that period starts. Add the missing half.

**Current behavior:**
The reporter framed this as "the skill description is action-framed". Triage found two things wrong
with that framing, and the corrected version is a stronger issue:

1. **The quoted text is not in the skill.** The phrase *"derive which action is outstanding"* is the
   `status` command's own description string in the CLI, which reaches an agent through `--help` and
   `--llms-full`. The skill is named `kleros-juror`, not `kleros-juror-status`, and its description
   is about committing and revealing.
2. **The gap is not action-framing, it is one-sidedness.** The skill's Timing section, the runtime
   deadline warnings emitted in `warnings[]`, and the `CONTEXT.md` **Deadline** glossary entry all
   already say the same true thing: the deadline is an upper bound, never an entitlement, and both
   periods end early once every juror has acted because `passPeriod` is permissionless.

   So the docs are loud about *"you may get less time than the deadline implies"* and silent about
   *"you always get the full window once the period starts"*. That silence is what the reporting
   agent filled in wrongly. A `passPeriod` that lands late costs the **dispute** time, never the
   juror, because the next period's timeout is measured from its own `lastPeriodChange`.

**Desired behavior:**
The clock-origin invariant appears on all three surfaces, alongside — not instead of — the
early-exit statement each already carries. The two are complementary: one bounds the window from
above, the other guarantees it from below.

The invariant, in the reporter's own words, which are good:

> each period's timeout is measured from that period's own start; a late `passPeriod` costs the
> dispute time, never the juror

**Key interfaces:**

- The `status` command's `description` string — the surface an agent reads *before* forming any time
  model. Keep it to its current one-or-two-sentence budget; this is a clause, not a paragraph.
- The skill's **Timing** section — it already states the early-exit half, so this is one sentence
  next to it.
- `CONTEXT.md`'s **Deadline** entry — the glossary definition already spells out
  `lastPeriodChange + timesPerPeriod[period]`; it should say which of those two moves and which does
  not.
